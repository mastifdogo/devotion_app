Audio

Choose what reads each kind of text. Piper runs on this server. A speech API is a service on the internet (OpenAI's, or one that works the same way). A local speech server is a text-to-speech model you run yourself on your network (Kokoro-FastAPI, openedai-speech, LocalAI and others that speak OpenAI's speech API).

Entries are read when they arrive. A Bible chapter is read the first time someone presses Listen on it (that first time takes a moment, longer with Piper on a small server) and is kept on the server after that. The speech API never reads the Bible by itself: only for a person who picks it as their Bible voice in the app's settings, chapter by chapter as they listen. The app carries the King James Version; this server downloads it the first time someone listens to it.

Reads every chapter of that version ahead of time, in the voice the Bible is read in, so nobody waits for a chapter. It takes many hours (days on a small server) and roughly 2 GB of disk for a whole Bible; entries and chapters people ask for take their turn in between. It carries on after a restart, skips chapters already kept, and can be stopped at any time. A version the server does not have yet is downloaded first.

Piper

What Piper reads is made in every voice here, and each person picks the voice they listen to in the app; the default voice is what they hear until they choose (and what reads the Bible). A newly downloaded voice is made for existing entries in the background.

Speech API

The text is sent to this service and read in its voice. The service bills the account its API key belongs to; people using the app or the website are never charged. Without a key, Piper reads instead.

Local speech server

The address of the server's OpenAI-style API, ending in /v1; this server must be able to reach it. Nothing leaves your network. Until an address is saved, Piper reads instead.

A change applies to audio made from now on, and entries that have none in the new voice get it in the background; use "Redo audio" on an entry to remake it.

Android app

Type this address into the app. It asks each new person for their name; notes and highlights are kept per person. Anyone on your network who knows the address can read the entries, so don't expose this port to the internet.

Archive

Entries older than this are moved to a network share (a text file and the MP3 for each) and only their title, date and summary stay on the server. Phones keep what they have already downloaded. Nothing is moved until a share is set.

Backup

Saves a copy of this server's database to a network share: every entry, person, highlight and comment, and these settings (including the Gmail connection and API keys, so keep the share private). Audio, voices, Bibles and wallpapers are not in it; they are made or downloaded again after a restore.

Times are in the time zone chosen on the Gmail tab. Several times can be given, like 03:00, 15:00.

Backups on the share

Restoring replaces everything on this server with the backup and restarts it; the current database is kept on the server as devotion.db.before-restore.
